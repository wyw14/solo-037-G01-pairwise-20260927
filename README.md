# WaveLab

WaveLab is a local HTTP service for tow-tank experiments. The original equipment and interlock pages expose a fixed commissioning diagnostic scenario. Operator measurements are a separate live data path.

Set `WAVELAB_DATA_DIR` to choose the archive directory (default `data/wavelab`). `POST /api/measured-runs` accepts `name`, `model_name`, `section`, and `carriage`. `POST /api/measured-runs/{id}/evidence` accepts `kind` (`wave_time` or `force`), `source_id`, finite `value`, and `recorded_at` in RFC3339 form. `GET /api/measured-runs`, `GET /api/measured-runs/{id}`, and `GET /api/measured-runs/{id}/analysis` return the supplied records and wave/force summary. Measurements are committed to `operator-measurements.json` before they are published in memory, and are reloaded when the service restarts. The archive does not automatically grant a safety permit or drive hardware.

Ship model geometry and load profiles are archived separately in `model-profiles.json`. `POST /api/model-profiles` accepts `model_name`, `params` (`geometry` with length/beam/depth/draft in meters, `load` with displacement and load condition, `installation` with tow point, mount type and appendages), and a `note`; each call appends a new immutable configuration version, creating the model on first use. `GET /api/model-profiles` and `GET /api/model-profiles/{name}` return the registered models with their full version history. Water conditions per tank section are recorded with `POST /api/section-conditions` (`section`, `depth_meters`, optional `width_meters`) and listed with `GET /api/section-conditions`; they are stored in `section-conditions.json`.

When a measured run is created for a registered model, the current profile version is pinned on the run, so later reconfiguration never changes what an earlier run used. `GET /api/measured-runs/{id}/compatibility` evaluates that pinned version against the section's latest water conditions and reports a `compatible`/`marginal`/`incompatible`/`unknown` verdict with per-check detail (under-keel clearance, depth-to-draft ratio, blockage ratio). The evaluation is advisory only and does not block runs or grant permits.

The `internal/probe`, `internal/force`, `internal/permit`, `internal/carriage`, `internal/track`, `internal/wave`, `internal/absorber`, and `internal/journal` packages provide component logic for further work. Their diagnostic use does not imply that the original HTTP pages accept real sensor streams.
